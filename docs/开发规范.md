# FinCoreCms 开发规范

> 编码规范、Git 提交规范、Code Review 流程

---

## 1. Java 编码规范

### 1.1 命名规范
- **类名**：UpperCamelCase，如 `OrderService`
- **方法名**：lowerCamelCase，如 `calculateFee()`
- **常量**：UPPER_SNAKE_CASE，如 `MAX_RETRY_COUNT`
- **包名**：全小写，如 `com.fincore.order.service`

### 1.2 金额处理
- **强制使用 `BigDecimal`**，禁止使用 `float`/`double`
- 金额计算统一使用 `BigDecimal` 的 `add/subtract/multiply/divide` 方法
- 数据库使用 `DECIMAL(18,2)` 或 `DECIMAL(18,4)`

### 1.3 异常处理
- 业务异常统一使用自定义 `BusinessException`
- Controller 层不捕获异常，由 `GlobalExceptionHandler` 统一处理
- 资金操作异常必须记录审计日志

### 1.4 日志规范
- 使用 Lombok `@Slf4j`
- 关键资金操作记录 INFO 级别
- 异常记录 ERROR 级别，包含完整堆栈

## 2. Vue 前端规范

### 2.1 组件命名
- 页面组件：`views/` 目录，PascalCase，如 `OrderList.vue`
- 公共组件：`components/` 目录，PascalCase，如 `DataTable.vue`

### 2.2 权限指令
- 按钮级权限使用 `v-permission="'order:create'"` 指令
- 路由级权限在 `router.beforeEach` 中校验

---

## 3. Git 提交规范

### 3.1 分支策略
- `main`：生产分支，受保护
- `develop`：开发分支
- `feature/xxx`：功能分支
- `bugfix/xxx`：修复分支

### 3.2 提交信息格式

```
<type>(<scope>): <subject>

type: feat|fix|docs|style|refactor|test|chore
scope: order|payment|fund|report|gateway|common|web|miniapp
```

示例：
```
feat(order): 订单批量费用计算引擎
fix(payment): 修复付款审批状态流转异常
```

### 3.3 禁止事项
- 禁止 `--force` 推送
- 禁止直接提交到 `main` 分支
- 禁止提交密钥文件（API Key、密码等）

---

## 4. Code Review 规范

### 4.1 检查要点
- [ ] 金额计算是否使用 BigDecimal
- [ ] 资金操作是否有审计日志
- [ ] 是否遵循命名规范
- [ ] 是否有单元测试覆盖核心逻辑
- [ ] SQL 是否有索引支持

### 4.2 流程
1. 提交 MR/PR 到 `develop` 分支
2. 至少 1 位 Reviewer 审核通过
3. CI 流水线通过后方可合并

---

## 5. 数据库规范

- 表名：`t_` 前缀，如 `t_order`
- 字段名：小写下划线，如 `order_no`
- 必备字段：`id`, `create_time`, `update_time`
- 金额字段：`DECIMAL(18,2)` 或 `DECIMAL(18,4)`
- 索引命名：`idx_字段名`
