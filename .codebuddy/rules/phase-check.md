# ✅ Phase 完成检查

> 每个 Phase 执行完毕后，必须逐一核对所有子任务是否真正完成，不得遗漏。

## 新增/修改任务的前置规则 ⚠️

**当用户要求新增或修改 Phase 内的任务时，必须先执行以下两步，再动手写代码：**

1. **更新执行计划**：在 `财务管理模块执行计划.md` 中插入/修改对应任务行，编好 T 编号（如 `T3-9`），注明依赖和产出
2. **更新执行日志**：在 `docs/phase-logs/Phase-X-log.md` 的"产出文件"表格中追加新任务预计产出的文件清单

不完成这两步，不得开始编码。

## 检查流程

Phase 所有工作告一段落、准备向用户报告完成之前，执行以下检查：

### 1. 列出该 Phase 全部子任务

从 `财务管理模块执行计划.md` 中提取当前 Phase 的任务清单，明确列出每个 T 编号 + 任务名称。

### 2. 逐个核对完成状态

对每个子任务：

| 检查项 | 说明 |
|--------|------|
| 文件产出 | 该任务要求的产出文件是否已创建？ |
| 功能验证 | 该任务的核心功能是否已验证通过？（不只是写了代码） |
| 依赖就绪 | 下游依赖此任务的后续任务是否可正常推进？ |

### 3. 标记状态

```
T2-0  API 接口契约     ✅ 已创建 + 已完成
T2-1  Spring Cloud     ✅ 已配置 + 未验证启动
T2-12 数据层开发       ⚠️  代码已写 + 未编译验证
```

### 4. 未完成项处理

- 如所有任务 ✅ → 报告完成，更新 Linear + 日志
- 如有 ⚠️ 或 ❌ → **先补完再报告，不得跳过**

### 5. 输出检查结果

向用户展示检查清单，格式：

```
Phase X 完成检查：
  T-1  ✅
  T-2  ✅ 
  T-3  ⚠️ 未完成项：xxx
共计：3/3 完成（或 2/3，1 项待处理）
```
