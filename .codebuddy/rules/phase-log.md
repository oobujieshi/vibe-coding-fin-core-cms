# 📝 Phase 交互日志

> 每个 Phase 执行时，必须记录交互日志到 `docs/phase-logs/Phase-X-log.md`。

## 触发时机

当用户发出 Phase 执行指令时，创建日志文件 `docs/phase-logs/Phase-X-log.md`（X 为 Phase 编号）。

## 日志格式

每个日志条目必须遵循以下结构：

```markdown
# Phase X 执行日志

> 日期：YYYY-MM-DD HH:MM

---

## 用户原始输入

[用户原始输入，逐字记录]

---

## 优化后的提示词

[对用户原始指令进行清晰化、具体化后的版本，解决歧义、补充缺失上下文]

优化说明：
- [对原始提示词做了哪些具体改进，逐条列出]

---

## AI 执行摘要

[本阶段执行了哪些操作、关键输出和结果]

---

## 产出文件

| 文件 | 说明 |
|------|------|
| path/to/file | description |

---

## 待用户确认

[需要用户决策或确认的事项]
```

## 日志规则

1. 如 `docs/phase-logs/` 目录不存在则先创建
2. 用户每次发出新的 Phase 执行指令，创建**新的**日志文件（不覆盖已有日志）
3. 如同一 Phase 跨多次交互，追加到同一日志文件，用 `---` 分隔
4. "优化后的提示词"环节必须**先于 Phase 实际执行**完成，即先优化、记录，再动手
5. 优化说明需明确指出对原始输入做了哪些改进（如澄清歧义、补充上下文、细化范围等）

## 新增/修改任务时的日志同步 ⚠️

当 Phase 执行过程中新增或修改子任务时：

1. **任务执行前**：更新执行日志中的"产出文件"表格，添加新任务的预计产出文件
2. **任务执行后**：更新"产出文件"表格中该任务的实际产出文件路径
3. **Phase 结束时**：在"AI 执行摘要"中单独注明本次新增/修改了哪些任务
4. **测试报告**：如有新测试产出（如 `docs/test-report-phaseX.md`），必须在日志中列出
